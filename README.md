# ProfitLens-AI — Shop Health Checker

Turn a small e-commerce shop's raw metrics into a **verdict and an action plan**: one structured Health Report with an overall score (0–100), a verdict badge (healthy / watch / critical), six weighted dimension scores, a plain-language summary, and prioritized recommendations — with the prose generated by a self-hosted LLM on an **AMD Radeon Pro W7900D (ROCm)**.

> AMD Developer Hackathon Act III · Track 3 Commerce (+ Evolus additional track)

## Architecture

```
Next.js dashboard (shop picker, report cards)
        │  POST /api/check  (ShopData JSON)
        ▼
Scoring API — rubric v0.2 (deterministic, auditable)
        │  scores + report skeleton
        ▼
lib/llm.ts — engine=mock | llm
        │  (llm) POST /v1/chat/completions
        ▼
Qwen3-4B served by vLLM (OpenAI-compatible) on AMD Radeon Pro W7900D · ROCm
        │
        ▼
HealthReport JSON → dashboard renders it
```

**Dual engine by design:** the numeric scores always come from the deterministic rubric (`lib/scorer.ts`). When `VLLM_BASE_URL` is set, the summary / dimension comments / recommendations are generated by Qwen3-4B via vLLM (`engine: "llm"`). When the GPU endpoint is unreachable or unset, the app transparently falls back to built-in rule-based prose (`engine: "mock"`) — same scores, degraded prose, **never breaks**.

## Scoring rubric (v0.2)

Six dimensions, weighted:

| Dimension | Weight |
|---|---|
| Price competitiveness (position vs market average) | 0.20 |
| Review quality & volume | 0.20 |
| 30-day sales trend | 0.20 |
| Service (response rate, refund rate) | 0.20 |
| Listing completeness | 0.10 |
| Activity (days since last sale) | 0.10 |

Verdict bands: overall ≥ 70 → healthy · ≥ 50 → watch · else critical.
Guards: dormant shops (no sale in 30+ days) capped at 40; shops with no track record capped at 69. Full formulas: [doc/scoring-rubric.md](doc/scoring-rubric.md).

## Quickstart

```bash
git clone https://github.com/zxy-666666Max/ProfitLens-AI
cd ProfitLens-AI
cp .env.example .env     # leave VLLM_BASE_URL empty to run in mock mode
npm install
npm run dev              # http://localhost:3000
```

To run with the LLM engine, point `.env` at any OpenAI-compatible endpoint:

```
VLLM_BASE_URL=http://127.0.0.1:8000
VLLM_MODEL=Qwen/Qwen3-4B
```

Check `GET /api/health` → `{"mode": "llm"}` confirms the GPU endpoint is wired.

## The AMD stack

- Model: **Qwen/Qwen3-4B**
- Serving: **vLLM** (OpenAI-compatible API, port 8000), `--served-model-name Qwen/Qwen3-4B`
- Hardware: **AMD Radeon Pro W7900D (gfx1100, RDNA3)** on the AMD Anrui ROCm notebook instance
- Verify GPU load live: `rocm-smi` while clicking Analyze — utilization/VRAM spike on every report

## Grading harness

Our scorer is validated against the organizer's answer key:

```bash
npx tsx scripts/grade.ts
```

Result: **10/10 test shops match** the expected verdicts (`data/test-shops.json` + `data/test-shops.expected.json`). Deterministic: same input always produces the same scores.
